# The docs sidebar shows "api" instead of "API Reference", and the container-built changelog page is empty

## Problem

Two defects on the embedded Docusaurus docs site (`web/docs/`), both invisible in
local dev and only manifest in the shipped container:

1. **Sidebar label.** The left menu labels the API reference category `api`
   (the raw directory name) instead of a proper "API Reference". The sidebar is
   autogenerated from the folder structure
   ([sidebars.ts:6](web/docs/sidebars.ts:6)), and the label for a directory is
   supposed to come from a `_category_.json` inside it.
   [web/docs/.gitignore](web/docs/.gitignore) ignores the generated
   `/docs/api/*` but whitelists `!/docs/api/_category_.json` with the comment
   "The category label is kept" — **yet the file does not exist**, neither on
   disk nor in git (`git ls-files web/docs/docs/api/` is empty). So Docusaurus
   falls back to the directory name `api`.

2. **Empty changelog.** `/docs/changelog` is generated at build time by
   [gen-changelog.ts](web/docs/scripts/gen-changelog.ts), which reads the root
   `CHANGELOG.md` via the relative path `../../../CHANGELOG.md` (resolving to
   `/build/CHANGELOG.md` inside the image build). The docs-builder stage of the
   [Dockerfile](Dockerfile:67) copies `web/docs/`, the OpenAPI spec
   ([Dockerfile:86](Dockerfile:86)) — but **never copies the root
   `CHANGELOG.md`**. The script's deliberate fallback
   ([gen-changelog.ts:28-36](web/docs/scripts/gen-changelog.ts:28)) then writes
   the placeholder "No changelog available yet." So every container build ships
   an empty changelog page, while local `bun run start`/`build` (where the file
   exists) looks fine — which is why it went unnoticed.

## Proposal

1. Create and commit `web/docs/docs/api/_category_.json`:

   ```json
   {
     "label": "API Reference",
     "position": 900,
     "collapsed": true
   }
   ```

   (Pick a `position` that keeps it where it sits today — after the prose
   sections, before Changelog at `sidebar_position: 1000`. Verify
   `docusaurus gen-api-docs` does not clobber the file, and that
   `clean-api-docs` sparing/removing it doesn't matter since git restores it.)

2. Add to the docs-builder stage of the `Dockerfile`, before `bun run build`:

   ```dockerfile
   COPY CHANGELOG.md /build/CHANGELOG.md
   ```

## Validation

- Local docs build: `cd web/docs && bun run build` — sidebar category reads
  "API Reference"; `docs/changelog.md` carries the real releases (0.21.0 …).
- **Full container build** (`docker build .`), run the image, and check on the
  served site: `/docs` left menu shows "API Reference", `/docs/changelog` is
  populated. This is the gate that actually proves the fix, since both bugs
  only reproduce in the container build.
- Optionally deploy the image to solidping.k8xp.com (k8xp repo, kubectl context
  `k8xp`, ns `solidping-dev` — the main API deployment is the one serving
  `/docs`) and verify the two pages live.
