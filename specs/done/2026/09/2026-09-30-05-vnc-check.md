# Add a `vnc` check type: RFB handshake, auth-method audit, VNC-auth logon and screenshot

## Problem
SolidPing cannot monitor VNC servers. The only option today is a `tcp` check, which proves the port is open but not that an RFB server answers, which auth methods it offers, or that a login works. Exposed VNC with no authentication (security type 1) is a common and serious finding that nothing detects.

VNC (RFB, RFC 6143) is small enough to implement with the Go stdlib only. No third-party client library, unlike RDP's vendored `grdp` fork.

This spec covers levels 1 and 2. JS remote control is spec `2026-09-30-06`. VeNCrypt and Apple ARD auth are spec `2026-09-30-07`.

## Proposal
1. New package `server/internal/checkers/checkvnc/`, structured like `checkrdp`:
   - `protocol.go`: the pre-auth handshake. Read the 12-byte `RFB xxx.yyy\n` banner, reply with the highest version both sides support (3.3, 3.7, 3.8), read the security-types list (3.7+) or the single `uint32` type (3.3). On a type-0 list, read the server's reason string and report it.
   - `session.go`: the authenticated path. VNC auth (type 2) = DES-ECB of the 16-byte challenge, with the password truncated/zero-padded to 8 bytes and **each key byte bit-reversed** (`crypto/des`). Read `SecurityResult`, and on 3.8 the failure reason string. Send `ClientInit` with **shared-flag = 1** so the probe never disconnects an existing viewer. Parse `ServerInit` (width, height, pixel format, desktop name).
   - Screenshot: send `SetPixelFormat` (32 bpp true-colour, known shifts), `SetEncodings` [Raw (0), CopyRect (1)], a non-incremental `FramebufferUpdateRequest` for the whole screen, decode Raw and CopyRect rectangles into an `image.RGBA`, and PNG-encode it. Mirror `checkrdp`'s frame buffer and `ScreenshotPNG` (`server/internal/checkers/checkrdp/session.go:127`, `:364`). Ignore unknown message types gracefully (Bell, ServerCutText) and fail cleanly on an unexpected encoding.
   - `checker.go`: `VNCChecker` implementing the Checker interface. Without a password: handshake only. With a password: handshake + auth + ServerInit + optional screenshot, then close.
   - `samples.go`, `alias.go` like `checkrdp`.
2. `server/internal/checkers/checkvnc/config/`: `VNCConfig` with `host` (required), `port` (default 5900), `timeout`, `password` (secret, via `SecretFields`), `requireAuth` (fail when security type 1 "None" is offered), `screenshot` (bool, only with a password). Validation like `server/internal/checkers/checkrdp/config/validate.go`. Username is not used by type 2 (it's reserved for spec 07).
3. Output details: `rfbVersion`, `securityTypes` (names + numbers), `desktopName`, `width`, `height`, and timings (connect, handshake, auth, first frame).
4. Failure reasons with stable codes: connection refused/timeout, not an RFB server (bad banner), `NO_AUTH_OFFERED` / auth-type unsupported (e.g. only VeNCrypt or ARD offered, with the list in the message), `AUTH_FAILED` (with the server's reason), too many attempts (RealVNC/TightVNC lockout messages), no frame in time.
5. Wiring:
   - `CheckTypeVNC CheckType = "vnc"` in `server/internal/checkers/checkerdef/types.go` (next to `CheckTypeRDP`, line 232).
   - `server/internal/checkers/registry/registry.go:154` and `server/internal/checkers/configregistry/configregistry.go:149` and `:259`.
   - Add `vnc` to the three check-type enums in `server/internal/app/openapi/openapi.yaml` (lines ~10269, 10861, 11193).
   - Add `"vnc"` to `captureTypes` in `server/internal/handlers/checkscreenshots/service.go:88` and `CAPTURE_TYPES` in `web/dash0/src/lib/check-screenshots.ts:5`.
   - dash0: form type in `web/dash0/src/components/checks/form/types/` (same place as rdp in `misc.tsx`, `index.ts`, `common.ts`), `check-type-identity.tsx`, `check-type-docs-anchors.ts`, locale keys in every locale.
   - Docs: a `vnc` section in `web/docs/docs/features/check-types.md`, and a CHANGELOG entry.

## Tests
- `checkvnc/protocol_test.go`, against an in-process fake RFB server (`net.Pipe` or a loopback listener):
  - version negotiation for 3.3, 3.7 and 3.8 servers;
  - type-0 security list with a reason string gives a down result carrying that reason;
  - non-RFB banner (e.g. an SSH banner) gives "not an RFB server";
  - `requireAuth: true` + server offering None gives down; the same server with `requireAuth: false` gives up (positive control).
- `checkvnc/session_test.go`:
  - DES response matches a known vector (password `password`, fixed challenge, expected 16 bytes), and a test that fails if the bit reversal is dropped;
  - wrong password: fake server replies SecurityResult=1 + reason, giving `AUTH_FAILED` with the reason;
  - ClientInit sends shared-flag = 1 (assert the byte on the fake server side);
  - Raw + CopyRect rectangles decode to the expected pixels; PNG round-trip gives the same dimensions as ServerInit;
  - server offering only VeNCrypt (19) or ARD (30) with a password configured gives the auth-type-unsupported failure, listing the offered types.
- `checkvnc/config/config_test.go`: required host, port range, `screenshot` without `password` rejected, password redacted via `SecretFields`.
- `checkvnc/vnc_live_test.go` (`//go:build slowtests`, like `server/internal/checkers/checkrdp/xrdp_live_test.go`): a TigerVNC or x11vnc container, check with password and screenshot, assert a non-empty PNG of the right size.
- dash0: `check-type-identity.test.ts` and `check-screenshots.test.ts` include `vnc`.

## Open questions
- **Default for `requireAuth`?** Recommended: `true`. Exposed no-auth VNC is almost always a mistake, and users of intentionally open internal VNC can switch it off.
- **Period floor for authenticated runs?** RDP uses 15 minutes (`server/internal/checkers/checkrdp/config/config.go:46`) because a logon has side effects. A VNC connection attaches to the live console with no logon. Recommended: no special floor. Many servers do lock out after repeated wrong passwords, but a wrong password fails every run anyway.

## Resolved open questions
- `requireAuth` defaults to `true`. Users of intentionally open VNC can switch it off.
- No special period floor for authenticated runs (unlike RDP's 15 minutes). A VNC connection has no logon side effects.
