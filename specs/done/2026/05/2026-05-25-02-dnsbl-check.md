# DNSBL (blocklist) check type

## Context

SolidPing already ships 33 protocol checkers, so the product does **not** need broader
raw-protocol coverage — the marginal value of a 34th niche protocol is low and every one adds a
dependency, a flaky integration test, and a config form. The high-value, low-risk addition is a
**DNSBL / blocklist check**: "is this IP (or domain) listed on a DNS blocklist like Spamhaus?"

It directly complements the existing `email` + `smtp` + `domain` checks for the self-hosting /
mail-operator audience this codebase targets (Freebox line quality, LAN discovery, mail-protocol
checks). Mail-server operators care intensely about reputation, and there is no good self-hosted
tooling for it. Critically, it reuses the DNS plumbing already proven in
[`checkdns/`](../../server/internal/checkers/checkdns/) with **no new dependencies** — pure
`net.Resolver` lookups.

## Honest opinion

This is the cleanest of the candidate additions because it is *not* a new protocol integration —
it is the DNS checker with inverted semantics. Keep v1 deliberately small: binary up/down, a
configurable list of zones, no per-list severity, no RHSBL, no authenticated Spamhaus DQS. Those
are easy follow-ups and would only muddy the first cut.

Two things are non-obvious and must be gotten right (see below): the **NXDOMAIN inversion** and the
**resolver constraint**. Everything else is mechanical.

## Goal

- New check type `dnsbl` in the checker registry.
- Config: a target (IPv4 or hostname) + an optional, overridable list of blocklist zones + optional
  custom resolver + timeout.
- On each execution, query every configured zone and report `Up` when the target is listed on **zero**
  blocklists, `Down` when listed on **one or more**, recording which lists flagged it.
- Record `listings` count + per-zone results in the structured `Output` for display.

## Non-goals

- RHSBL / domain-based zones (e.g. `dbl.spamhaus.org`) — v1 only does IP-based listing. (follow-up)
- Spamhaus DQS authenticated-zone keys (a secret field). (follow-up)
- Per-listing severity or a "listed on N lists" threshold knob — v1 is binary. (follow-up)
- Removal/delisting workflows or notifications beyond the standard incident path.

## The two non-obvious details

### 1. NXDOMAIN is the *good* answer (inverse of checkdns)

In a DNSBL, a query for `<reversed-ip>.<zone>` means:

- Returns an `A` record (typically `127.0.0.x`) → the IP **is listed** → bad.
- `NXDOMAIN` (host not found) → **not listed** → clean → good.
- Timeout / SERVFAIL / other error → **inconclusive** for that zone — recorded in `Output`, but
  **not** counted as a listing.

This is the exact inverse of [`checkdns/checker.go:146-187`](../../server/internal/checkers/checkdns/checker.go),
where `net.DNSError.IsNotFound` maps to `StatusDown`. The DNSBL checker must treat `IsNotFound` as
"clean".

### 2. Resolver constraint (Spamhaus & friends block public resolvers)

Spamhaus and several others **block queries that arrive via public resolvers** (8.8.8.8 / 1.1.1.1)
and rate-limit high volume. Therefore:

- Default to the worker's own system resolver (`&net.Resolver{}`, like `checkdns`).
- Expose an optional `nameserver` (`host:port`) for users who run a local recursive resolver.
- Use a conservative default period (blocklist status changes slowly): `DefaultPeriod: 1h`,
  `MinPeriod: 15m`.
- Default zones must exclude dead lists — **do not** include SORBS (`dnsbl.sorbs.net`), shut down in
  2024.

## Check config

New file `server/internal/checkers/checkdnsbl/config.go`:

```go
type DNSBLConfig struct {
    Target     string        `json:"target"`               // IPv4 address or hostname
    Blocklists []string      `json:"blocklists,omitempty"` // DNS zones; defaults applied when empty
    Nameserver string        `json:"nameserver,omitempty"` // custom resolver host:port (optional)
    Timeout    time.Duration `json:"timeout,omitempty"`
}
```

Default zones (used when `Blocklists` is empty):
`zen.spamhaus.org`, `bl.spamcop.net`, `b.barracudacentral.org`, `dnsbl-1.uceprotect.net`.

`FromMap` / `GetConfig` mirror [`checkdns/config.go`](../../server/internal/checkers/checkdns/config.go),
including the `[]any → []string` coercion for the `blocklists` array (JSONB decodes arrays as `[]any`;
see `checkdns/config.go:84-115`). Use `checkerdef.NewConfigError(field, msg)` for validation errors.

`Validate()` checks:
- `Target` is non-empty.
- `Nameserver`, if set, is in `host:port` form (mirror `checkdns/checker.go:82-86`).
- `Timeout`, if set, is `> 0` and `<= 60s`.

### Status mapping

| Condition | Status |
|---|---|
| Target is a hostname that fails to resolve to any IP | `Down` (cannot be checked) |
| Listed on ≥1 blocklist (A record returned) | `Down` |
| Listed on 0 blocklists (all NXDOMAIN / inconclusive) | `Up` |
| Every zone query was inconclusive (all timed out) | `Timeout` |

### Result body

```json
{
  "target": "203.0.113.10",
  "target_ip": "203.0.113.10",
  "listed_on": ["zen.spamhaus.org"],
  "clean": ["bl.spamcop.net", "b.barracudacentral.org"],
  "inconclusive": ["dnsbl-1.uceprotect.net"],
  "return_codes": { "zen.spamhaus.org": ["127.0.0.2"] }
}
```

Metrics: `listings` (count), `blocklists_checked` (count), `query_time_ms`.

## Checker implementation

New package `server/internal/checkers/checkdnsbl/` mirroring `checkdns/`:

### `checker.go`

```go
type DNSBLChecker struct{}

func (c *DNSBLChecker) Type() checkerdef.CheckType { return checkerdef.CheckTypeDNSBL }

func (c *DNSBLChecker) Validate(spec *checkerdef.CheckSpec) error { /* see config */ }

func (c *DNSBLChecker) Execute(ctx context.Context, config checkerdef.Config) (*checkerdef.Result, error) {
    cfg, err := checkerdef.AssertConfig[*DNSBLConfig](config)
    // 1. Resolve target → []IP (if already an IP, use as-is).
    // 2. For each IP × each zone: query <reversed-ip>.<zone> via the lookuper.
    //    A record  -> listed; NXDOMAIN -> clean; other err -> inconclusive.
    // 3. Build Result (status per table above) + Metrics + Output.
    // Return (*Result, nil) for all check outcomes; (nil, err) only for internal errors.
}
```

**Testability seam.** `net.Resolver` is a concrete type, so introduce a tiny interface to inject a
fake in tests and avoid hitting the network:

```go
type hostLookuper interface {
    LookupHost(ctx context.Context, host string) ([]string, error)
}
```

The checker holds a `lookuper hostLookuper`; in production it is built from `&net.Resolver{}` (or a
custom-`nameserver` resolver, reusing the dial closure in `checkdns/checker.go:238-252`). Tests inject
a map-backed fake.

the **injected fake lookuper** so tests never touch the network:

- `TestDNSBLConfig_FromMap`: parsing, `blocklists` `[]any` coercion, defaults, bad types → errors.
- `TestDNSBLChecker_Validate`: empty target, bad nameserver, out-of-range timeout.
- `TestReverseIP`: `1.2.3.4` → `4.3.2.1` (and reject non-IPv4).
- `TestDNSBLChecker_Execute`:
  - listed on one zone (fake returns `127.0.0.2`) → `Down`, `listed_on` populated.
  - clean on all zones (fake returns NXDOMAIN) → `Up`.
  - mixed clean + inconclusive → `Up`, `inconclusive` populated.
  - all zones inconclusive (all error) → `Timeout`.
  - hostname target resolving to multiple IPs → each IP checked.
- Optional network-gated integration test against `127.0.0.2` on `zen.spamhaus.org`, skipped when a
  network/CI flag is unset.
