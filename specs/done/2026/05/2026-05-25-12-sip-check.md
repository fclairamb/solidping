# SIP check type

## Context

SolidPing ships 34 protocol checkers, and the DNSBL spec rightly noted that raw-protocol breadth is
not the product's need. SIP clears that bar anyway: it adds **no dependency** (SIP is a text protocol
like HTTP — OPTIONS/REGISTER are crafted and parsed over stdlib `net`; digest auth is `crypto/md5`),
it needs **no migration** (JSONB config + existing encrypted `*_private` columns), and it serves the
codebase's actual self-hosting / home-lab audience: people running Asterisk / FreePBX / Kamailio, and
French Freebox users who get an ISP SIP line (we already ship `freebox_line`). Monitoring a PBX or SIP
trunk is squarely in that wheelhouse.

## Honest opinion

This is a worthwhile addition *if it stays a reachability + registration probe* and does not drift
toward call/media testing. The clean v1 is: a SIP **OPTIONS** ping (the universal SIP keep-alive) for
reachability, plus an optional **REGISTER** with credentials to prove auth works. Both are pure
text-over-socket. The moment someone asks for INVITE/RTP/call-quality, stop — that needs a media
stack and belongs in a different product.

Two things are non-obvious and must be gotten right (below): the **"any valid SIP response = Up"
semantic** (the SIP analogue of DNSBL's NXDOMAIN inversion), and the **401-challenge digest-auth
REGISTER flow**. Everything else is mechanical.

## Goal

- New check type `sip` in the checker registry.
- Reachability via **OPTIONS** over UDP / TCP / TLS; any well-formed SIP response (2xx, but also
  401/403/404/405…) means the server is alive → `Up`.
- Optional **REGISTER** mode: when credentials are supplied, perform a digest-auth registration and
  base `Up`/`Down` on whether registration succeeds (200 OK).
- Record the SIP status code/reason, transport, and `Server`/`User-Agent` header in `Output`;
  response time in `Metrics`.

## Non-goals

- INVITE / call setup / RTP / media or call-quality testing. (out of scope, needs a media stack)
- SUBSCRIBE/NOTIFY, MESSAGE, or dialog/transaction state beyond a single request/response.
- Full RFC 3261 UDP retransmission timers — v1 does a single send with a deadline (note below).
- `sip:`/`sips:` URI parsing through `urlparse` — SIP URIs are `sip:user@host`, not `scheme://...`,
  so v1 uses explicit `host`/`port`/`transport` fields instead. (possible follow-up)

## The two non-obvious details

### 1. Any valid SIP response = Up (the SIP inversion gotcha)

For an **OPTIONS** probe, the server proves it is alive by speaking SIP at all. A `200 OK` is ideal,
but `401`/`407` (auth required), `403`, `404`, `405` (method not allowed), `486`, etc. are **all**
valid SIP responses from a live server and must map to `Up`. `Down` is reserved for: no response
(→ `Timeout`), connection refused / reset, or a non-SIP / unparseable reply (no `SIP/2.0` status
line). This is the OPTIONS analogue of treating HTTP 4xx as "server is up." An optional
`expected_status` config (e.g. `"200"` or `"200,405"`) lets stricter users narrow this; when set, a
non-matching but valid SIP response is `Down`.

For **REGISTER** mode the semantic is stricter and intuitive: only a final `200 OK` (after the digest
challenge) is `Up`; a repeated `401`/`403`/`407` after credentials were supplied is `Down` (auth
failed).

### 2. The digest-auth REGISTER flow (RFC 3261 §22 / RFC 2617, all stdlib)

REGISTER is a two-shot handshake:

1. Send `REGISTER sip:<domain> SIP/2.0` with no `Authorization`.
2. Server replies `401 Unauthorized` (or `407`) with `WWW-Authenticate: Digest realm=…, nonce=…,
   qop="auth", algorithm=MD5`.
3. Compute the digest (MD5):
   - `HA1 = MD5(username:realm:password)`
   - `HA2 = MD5("REGISTER":digestURI)` where `digestURI = "sip:<domain>"`
   - `qop=auth` → `response = MD5(HA1:nonce:nc:cnonce:auth:HA2)` (nc=`00000001`, random cnonce);
     legacy (no qop) → `response = MD5(HA1:nonce:HA2)`
4. Resend REGISTER (new `Via` branch, **incremented `CSeq`**, same `Call-ID`/From-tag) with the
   `Authorization: Digest …` header.
5. `200 OK` → registered → `Up`; another `401/403/407` → auth failed → `Down`.

Two pure, directly unit-testable helpers fall out: `parseAuthChallenge(header) map[string]string`
and `buildDigestAuthorization(challenge, method, uri, username, password) string`.

### Plus: message framing & transport

- Every request needs a unique `Via` (branch starts with the magic cookie `z9hG4bK`), `From` (with
  `tag`), `To`, `Call-ID`, `CSeq`, `Max-Forwards: 70`, `Content-Length: 0`. Correlate the response by
  `Call-ID`/`CSeq` (over UDP the branch is echoed back).
- **UDP**: one datagram out, read one datagram back under the deadline. Single send in v1 (no T1
  retransmission) — documented simplification.
- **TCP / TLS**: read the status line + headers; respect `Content-Length` for the (usually empty)
  body. TLS reuses the dial/verify pattern from `checktcp` (`tls_verify`, `tls_server_name`).
- Default ports: `5060` for udp/tcp, `5061` for tls.

## Check config

New file `server/internal/checkers/checksip/config.go`:

```go
type SIPConfig struct {
    Host          string        `json:"host"`                      // required
    Port          int           `json:"port,omitempty"`            // default 5060 (udp/tcp), 5061 (tls)
    Transport     string        `json:"transport,omitempty"`       // "udp" (default) | "tcp" | "tls"
    Mode          string        `json:"mode,omitempty"`            // "options" (default) | "register"
    Domain        string        `json:"domain,omitempty"`          // SIP domain/realm for AOR; defaults to Host
    Username      string        `json:"username,omitempty"`        // required for register
    Password      string        `json:"password,omitempty"`        // SECRET, required for register
    AuthUsername  string        `json:"auth_username,omitempty"`   // optional, if auth user != AOR user
    ExpectStatus  string        `json:"expect_status,omitempty"`   // optional, e.g. "200" or "200,405"
    Timeout       time.Duration `json:"timeout,omitempty"`         // default 5s
    TLSVerify     bool          `json:"tls_verify,omitempty"`
    TLSServerName string        `json:"tls_server_name,omitempty"`
}
```

`FromMap` / `GetConfig` mirror `checktcp/config.go` (per-field type checks, snake_case keys).

`Validate()` (mirror `checkudp/checker.go:33-64`):
- `Host` non-empty.
- `Port`, if set, in 1–65535 (default applied at execute time).
- `Transport`, if set, ∈ {`udp`,`tcp`,`tls`}.
- `Mode`, if set, ∈ {`options`,`register`}; when `register`, `Username` and `Password` required.
- `Timeout`, if set, `> 0` and `<= 60s`.

## Status mapping

| Mode | Condition | Status |
|---|---|---|
| any | hostname fails to resolve | `Error` |
| any | connection refused / reset | `Down` |
| any | no response before deadline | `Timeout` |
| any | reply is not parseable SIP (no `SIP/2.0` status line) | `Down` |
| options | valid SIP response, no `expect_status` set | `Up` |
| options | valid SIP response matching `expect_status` | `Up` |
| options | valid SIP response **not** matching `expect_status` | `Down` |
| register | `200 OK` after digest auth | `Up` |
| register | `401/403/407` after credentials supplied | `Down` |

## Checker implementation

New package `server/internal/checkers/checksip/`:

### `checker.go`

```go
type SIPChecker struct{}

func (c *SIPChecker) Type() checkerdef.CheckType { return checkerdef.CheckTypeSIP }
func (c *SIPChecker) Validate(spec *checkerdef.CheckSpec) error { /* see config */ }
func (c *SIPChecker) Execute(ctx context.Context, config checkerdef.Config) (*checkerdef.Result, error) {
    cfg, err := checkerdef.AssertConfig[*SIPConfig](config)
    // 1. defaults: transport=udp, port=5060/5061, timeout=5s, domain=host.
    // 2. resolve host (StatusError on failure, like checkudp:84-103).
    // 3. options: build OPTIONS, roundTrip, classify per status table.
    // 4. register: roundTrip unauthenticated REGISTER -> on 401/407 parse challenge,
    //    buildDigestAuthorization, resend with incremented CSeq -> classify.
    // Return (*Result, nil) for all check outcomes; (nil, err) only for internal errors.
}
```

Helpers (each independently testable):
- `buildRequest(method, cfg, branch, callID, fromTag, cseq, authHeader string) string` — assembles
  the SIP message with all required headers (`Via` branch `z9hG4bK…`, `Max-Forwards: 70`,
  `Content-Length: 0`).
- `roundTrip(ctx, cfg, request) (raw string, err error)` — dials udp/tcp/tls, sends, reads response
  under deadline; UDP = one datagram, TCP/TLS = status line + headers (+ `Content-Length` body).
  TLS via `tls.Client` with `InsecureSkipVerify=!cfg.TLSVerify` and `ServerName` (mirror `checktcp`).
- `parseStatusLine(raw) (code int, reason string, ok bool)` — `ok=false` when no `SIP/2.0` line.
- `parseAuthChallenge(header) map[string]string` and
  `buildDigestAuthorization(ch, method, uri, user, pass) string` — RFC 2617 MD5 digest.

Implement the optional `CheckerSamplesProvider`: an OPTIONS sample against a public SIP host
(e.g. an OpenSIPS/Asterisk demo) and a REGISTER sample with placeholder credentials.

## Tests

`checker_test.go` — table-driven, `t.Parallel()`, `testify/require` (per `server/CLAUDE.md`),
using **loopback listeners** (`net.ListenPacket("udp", "127.0.0.1:0")` / `net.Listen("tcp", …)`)
so tests never leave the host:

- `TestSIPConfig_FromMap`: parsing, defaults, bad types → errors.
- `TestSIPChecker_Validate`: empty host, bad transport/mode, register-without-credentials,
  out-of-range port/timeout.
- `TestParseAuthChallenge` / `TestBuildDigestAuthorization`: known RFC 2617 vectors (deterministic
  cnonce/nc) → exact `response=` hash.
- `TestSIPChecker_Execute_Options`: fake returns `200 OK` → `Up`; returns `405` → `Up`; returns
  `405` with `expect_status:"200"` → `Down`; returns non-SIP garbage → `Down`; listener closed /
  refused → `Down`; no reply → `Timeout`. Run the matrix across udp + tcp.
- `TestSIPChecker_Execute_Register`: fake returns `401`+challenge then `200` → `Up`; returns `401`
  twice → `Down`. Assert the second request carries a correct `Authorization: Digest` and an
  incremented `CSeq`.
- Optional network-gated integration test against a public demo SIP server, skipped unless a network
  flag is set.
