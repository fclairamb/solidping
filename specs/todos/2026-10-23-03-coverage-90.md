# Raise backend test coverage to 90% or above

## Problem

Backend coverage is gated at 80% (`COVERAGE_MIN: "80"` in `.github/workflows/ci.yml:312`,
`target: 80%` in `codecov.yml`). Spec 2026-09-29-06 set a ratchet rule: raise the minimum to the
last measured value whenever coverage improves. The goal now is 90% or above.

## Proposal
1. Measure the baseline: `make test-cover` (use `COVER_FULL=1` for the Postgres layer, which is what
   CI measures, `Makefile:393`). List the lowest-covered packages and functions with
   `go tool cover -func=server/coverage.out | sort -k3 -n | head -50`.
2. Add tests, biggest uncovered packages first, until the full-layer total is at least 90%. Test
   behaviour (table-driven, like the surrounding tests). Do not add tests that only execute lines
   without asserting anything, and do not exclude code from the profile to move the number
   (`scripts/coverage.sh filter`, `codecov.yml` `ignore:`).
3. Raise `COVERAGE_MIN` in `.github/workflows/ci.yml:312` and the `target` values in `codecov.yml`
   to 90 (or to the measured value if it is above 90, following the ratchet rule).
4. Update the coverage notes in `wiki/testing/test-layers.md` if they quote the threshold.

## Tests
- The new tests themselves, including the error paths of the code they cover.
- `scripts/coverage_test.sh` still passes.
- `make test-cover` with `COVER_FULL=1` reports a total of at least 90.0%.

## To verify
