# The docs API reference shows a hardcoded Base URL, so copied examples point at the wrong host

## Problem

SolidPing exposes its REST API through three surfaces, and after v0.18.3 two of
them resolve the API host correctly while the third still does not:

| Surface | Base URL comes from | Host-aware? |
|---|---|---|
| `/openapi` (Scalar explorer) | `window.location.origin`, injected by `server/internal/app/openapi/index.html` | ✅ |
| `/openapi.yaml` (raw spec) | rewritten per request from `requestOrigin(req)` — `server/internal/app/openapi_spec.go` | ✅ (v0.18.3) |
| **`/docs/api/*` (Docusaurus reference)** | **baked into every page at build time** | ❌ |

The docs reference is generated by `docusaurus-plugin-openapi-docs` (v5.0.2)
from the canonical spec
([docusaurus.config.ts:86](web/docs/docusaurus.config.ts:86),
`outputDir: "docs/api"`). Each generated page carries the operation in a
**base64 + zlib** blob in its `api:` frontmatter — which is why grepping the
generated MDX for a URL finds nothing. Decoded, the blob carries the spec's
`servers` list verbatim:

```json
[{"url": "https://solidping.io",  "description": "SolidPing cloud"},
 {"url": "http://localhost:4000", "description": "Local development server"}]
```

So the theme's **Base URL** control offers exactly those two entries on every
host. Browsing `solidping.k8xp.com/docs/api/get-current-user`, or any
self-hosted instance, still shows `https://solidping.io` / `http://localhost:4000`
— and a reader who copies an example aims it at a host they are not using.

The runtime rewrite added in v0.18.3 **cannot** reach this: the docs site is
generated at build time and embedded, so it never consults the live
`/openapi.yaml`.

Note `hideSendButton: true`
([docusaurus.config.ts:88](web/docs/docusaurus.config.ts:88)), so there is no
"try it" request to misfire. The damage is confined to what the page *tells* the
reader, and to any code sample rendered from the base URL.

### The trap: the docs host does not serve the API

The obvious fix — mirror `index.html` and use `window.location.origin` — is
**wrong on `docs.solidping.io`**, and silently so.

`handlerWithDocsHost` ([server.go:2345](server/internal/app/server.go:2345))
redirects every request on the docs host whose path does not start with `/docs`
into `/docs`:

```go
if docsHostMatches(req.Host, docsHost) && !strings.HasPrefix(req.URL.Path, "/docs") {
    http.Redirect(writer, req, "/docs"+req.URL.Path, http.StatusFound)
```

So `docs.solidping.io/api/v1/auth/me` never reaches the API — it bounces into
the documentation site. An unconditional origin override would therefore take
the one host where the base URL is currently *correct* (the cloud) and replace
it with a host where every API call is redirected away.

The docs are served at `/docs` on **every** host (the instance itself and the
docs host alike), so the fix has to distinguish the two cases at run time, in
the browser, from a static bundle.

## Proposal

Swizzle the theme's server/base-URL component so it prefers the current origin,
**except** where that origin is known not to serve the API.

### 1. Resolve the base URL in the browser

- Swizzle the `docusaurus-theme-openapi-docs` component that renders the Base
  URL control (the `ApiExplorer` server selector — confirm the exact component
  name against the installed v5.0.2 before writing the override; swizzle
  `--eject` only that one component, not the whole theme).
- Resolution order:
  1. If the current origin is a **known docs host** → use the spec's first
     declared server (the cloud). This keeps `docs.solidping.io` correct.
  2. Otherwise → use `window.location.origin`, since the instance serving the
     docs is the instance serving the API.
- Keep the spec's own `servers` entries available in the control rather than
  replacing the list outright, so a reader on the docs host can still pick
  `localhost` deliberately. The change is about which entry is **selected and
  offered first**, not about deleting choices.

### 2. Tell the bundle what a docs host is

The docs bundle is static, so it cannot read `server.docs_host`. Expose it at
build time:

- Add a `customFields` entry in
  [docusaurus.config.ts](web/docs/docusaurus.config.ts) — e.g.
  `docsHosts: ["docs.solidping.io"]`, overridable from an env var so a fork or a
  staging docs host can set its own.
- Read it in the swizzled component via `useDocusaurusContext()`.
- Match on hostname only, case-insensitively, ignoring port — mirroring
  `docsHostMatches` server-side so the two cannot disagree.

### 3. Tests

- Unit-test the resolver as a pure function (origin, docsHosts, spec servers) →
  chosen base URL. Cover: an instance host wins over the spec's list; a docs
  host falls back to the cloud and **never** returns the docs origin; an unknown
  host falls back to the origin; an empty/missing `docsHosts` behaves like "not
  a docs host". Include the positive control — without one, a resolver that
  always returned the cloud would pass every docs-host case.
- Guard the build: `make build-docs` must stay green (it is the gate that caught
  the broken `/docs/api` link in v0.18.3).
- If a swizzled component is hard to unit-test in isolation, extract the
  resolution into a plain module and test that; the component becomes a thin
  caller.

### Notes

- Do **not** change `openapi.yaml`'s static `servers:` list. The docs site is
  also published at `docs.solidping.io`, where the cloud entry is the right
  answer, and the build-time reference legitimately advertises the cloud. This
  spec changes what the *browser* selects, not what the spec declares.
- The runtime rewrite in `server/internal/app/openapi_spec.go` is the model for
  the precedence logic but shares no code with it — one is Go on the server, the
  other TypeScript in a static bundle.
- Swizzling pins you to the theme's internals: leave a comment naming the theme
  version the override was written against
  (`docusaurus-theme-openapi-docs@5.0.2`), so a future upgrade knows to re-check
  it.

## Implementation Plan

1. **Pure resolver** — new `web/docs/src/lib/apiBaseUrl.ts`, no React and no
   Docusaurus imports so it is unit-testable on its own:
   - `hostnameOf(originOrHost)` — hostname only, lowercased, port stripped,
     tolerant of a bare host without a scheme. Mirrors the Go
     `docsHostMatches` semantics (`server/internal/app/server.go`).
   - `isKnownDocsHost(origin, docsHosts)`.
   - `resolveApiServers(origin, docsHosts, specServers)` — the ordered list the
     Base URL control should offer. Docs host → the spec's list untouched (its
     first entry, the cloud, stays selected, and the docs origin is never
     injected). Otherwise → the current origin first, with the spec's entries
     kept after it (moved, not duplicated, if the origin is already declared).
     Never mutates its input, and is idempotent.
   - `resolveApiBaseUrl(...)` — `resolveApiServers(...)[0]?.url ?? ""`, the
     `(origin, docsHosts, specServers) → base URL` function the spec asks for.
   - `sameServerUrls(a, b)` — used by the component to stop re-dispatching.
   - `docsHostsFrom(customFields)` — coerces the build-time value.

2. **Build-time docs-host list** — `customFields.docsHosts` in
   `web/docs/docusaurus.config.ts`, defaulting to `["docs.solidping.io"]` and
   overridable with `SP_DOCS_HOSTS` (comma-separated) for a fork or a staging
   docs host.

3. **Swizzle just the Base URL control** — `docusaurus-theme-openapi-docs@5.0.2`
   renders it from `@theme/ApiExplorer/Server`, whose value and option list come
   from the redux `server` slice preloaded in `@theme/ApiItem`. Two small
   overrides, both wrappers rather than copies:
   - `web/docs/src/theme/ApiExplorer/Server/slice.ts` — re-exports the theme
     slice and adds a `server/setServerOptions` action, because the theme's
     `setServer` reducer only accepts a URL already present in `state.options`.
   - `web/docs/src/theme/ApiExplorer/Server/index.tsx` — renders
     `@theme-original/ApiExplorer/Server` and, on mount, dispatches the resolved
     option list plus the preferred selection. Because the code samples read the
     same `state.server.value`, the rendered `curl` examples follow the control.

4. **Tests** — `web/docs/src/lib/apiBaseUrl.test.ts` run with `bun test`
   (`test:unit` script + a `test-docs` Makefile target + a CI step in the docs
   job), including the positive control that an instance host wins over the
   spec's list, so an always-return-the-cloud resolver cannot pass.

5. **Gate** — `make build-docs` and `make test-docs`. No Go changes;
   `openapi.yaml`'s `servers:` list is left alone.
